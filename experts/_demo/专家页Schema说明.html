给专家页加 Person Schema —— 是什么、干什么

本页用于向团队说明结构化数据（Person Schema）的原理与价值，并示范海鑫汇 GTN 现有 12 位专家顾问的结构化数据草案。
注意：本页为说明/评审用途，非对外正式页面。

一、是什么

Schema（结构化数据）是嵌在 HTML 里的一段机器可读的 JSON（JSON-LD 格式），用标准词汇（schema.org）告诉 AI："这个页面上的人是谁、是什么身份、擅长什么"。

海鑫汇主站 index.html 里已经有一个 Organization 的 JSON-LD（声明"海鑫汇是一个组织"）。但专家页（如 experts/donglixin/index.html）目前大部分已带有 ProfilePage + Person 的 JSON-LD——对 AI 来说，这些结构化数据能明确"某人是海鑫汇的专家顾问、是什么身份、knowsAbout 哪些领域"。

示意（以创始人为例，姓名严格取自已确认页面）： 
// 嵌在 <head> 中的 JSON-LD 示意
{
  "@type": "Person",
  "name": "董立鑫",
  "jobTitle": "海鑫汇 Global Talent Network 创始人",
  "affiliation": { "@type": "Organization", "name": "海鑫汇 Global Talent Network" },
  "knowsAbout": ["企业全球化", "国际商业连接", "产业数字化"],
  "url": "https://gtn-global.netlify.app/experts/donglixin/"
}

二、干什么（具体动作）

如果授权执行，我会做三件事：

  1. 读现有专家页，提取每位专家的真实姓名、职务、专长领域（以页面实际内容为准，不自行编造）。
  2. 在每位专家页的 <head> 里确保有一段 Person JSON-LD（现有页已含，可补充 affiliation 字段以链向组织）。
  3. 把专家与组织的关系链起来（affiliation 指向海鑫汇），强化 GTN 的"实体关系"。
对 GEO 的意义：当用户问 ChatGPT "中国机械企业出海该找什么专家"，AI 能从结构化数据确认"某人是海鑫汇的全球化战略专家，knowsAbout 出海"——从而更可能引用/推荐该专家与海鑫汇网站。这比 sitemap 更直接地影响 AI 引用。
监管边界（重要）：专家中部分人为上市公司高管，受法规监管。现有专家页文字均经你 Word 稿逐字确认，绝不动原文。Person Schema 中的 name / jobTitle / knowsAbout 仅取自你已确认页面，不新增任何对外表述。产业归属标签仅作草案，须由你拍板后方可写入。
